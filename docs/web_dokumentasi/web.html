Pustaka

Web dan data

Server HTTP, template, cookie dan sesi, WebSocket, klien HTTP, dan SQLite.

Semua yang dibutuhkan aplikasi web ada di namespace dok:: dan http::, tanpa pustaka tambahan.

Server

dok::serve memblokir dan menangani tiap koneksi di thread-nya sendiri. Argumen ketiga mengatur alamat (bawaannya 0.0.0.0; pakai "127.0.0.1" supaya cuma bisa diakses dari mesin sendiri).

Request (req)Isi
method, path"GET", "/sapa/Ani"
paramsbagian :nama dari pola rute, dibaca req.params.nama
querypasangan dari ?a=1&b=2; ambil dengan dok::query_get(req.query, "a")
headersambil dengan dok::header_get(req.headers, "Content-Type")
body, body_bytesbadan sebagai teks; kalau bukan teks UTF-8, body bernilai nil dan isinya di body_bytes

Handler boleh mengembalikan teks (jadi 200 text/plain), hasil dok::text, dok::html, dok::json_response, dok::redirect, dok::response(kode, isi), dok::binary(byte), atau Result (Err jadi 500).

Middleware

dok::router_use berjalan sebelum rute dicari; mengembalikan nil berarti lanjut, mengembalikan respons berarti berhenti di situ. dok::router_after berjalan sesudah handler dan boleh mengubah responsnya.

Template

dok::render mengisi {{ nama }} dan meloloskan HTML-nya, jadi isian dari pengguna aman ditampilkan. {{& nama }} menyisipkan apa adanya. Ada juga {{#if}}…{{else}}…{{/if}} dan {{#each}}…{{/each}}.

Pelolosan HTML cuma melindungi teks dan nilai atribut berkutip, jadi dok::render membaca di mana sebuah {{ nama }} duduk. Nilai di atribut URL (href, src, action, …) yang berskema selain http, https, mailto, tel diganti #jrg-url-ditolak. Nilai di dalam <script>/<style>, di atribut on*/style, di atribut tanpa tanda kutip, atau di tempat nama atribut adalah Err: taruh datanya di atribut data-* yang berkutip.

dok::render_file(berkas, data) membaca templatnya dari berkas.

Cookie, sesi, dan sandi

  • Sesi ditandatangani, tidak dienkripsi: isinya bisa dibaca siapa pun, tapi tidak bisa diubah tanpa kuncinya. Simpan kuncinya di variabel lingkungan, bukan di kode.
  • password_hash memakai PBKDF2-HMAC-SHA256 dengan garam acak per sandi.
  • dok::cookie_set(resp, nama, nilai, opsi) memasang cookie dengan HttpOnly dan SameSite=Lax secara bawaan; dok::cookie_get(req, nama) membacanya.

Token CSRF

Formulir yang mengubah sesuatu (POST, PUT, DELETE) membawa token yang dibuat server untuk sesi itu. Situs lain bisa membuat peramban korban mengirim formulir, tapi tidak bisa membaca tokennya.

  • Argumen ketiganya, ikatan, adalah id sesi: token sesi lain ditolak, jadi penyerang tidak bisa memakai token dari sesinya sendiri. Ikatan kosong ditolak.
  • Token berumur 12 jam; argumen keempat csrf_verify mengubahnya (dalam detik).
  • Rahasianya paling sedikit 32 byte. Taruh tokennya di <input type="hidden"> lewat dok::render, dan periksa sebelum mengerjakan permintaan.

WebSocket

Rute WebSocket hidup di router yang sama dengan rute HTTP biasa.

ws_recv menunggu pesan berikutnya dan menjawab None saat koneksinya ditutup. Pesan biner datang sebagai array byte.

Klien HTTP

http::get, post, put, delete, dan request menjawab Result berisi status, headers, body, dan ok. HTTPS memakai libssl milik sistem. http::unduh menulis langsung ke berkas, jadi aman untuk unduhan besar, dan tidak mengikuti pengalihan dari https:// ke http://.

Kalau URL-nya datang dari pemakai (pratinjau tautan, webhook, pengunduh gambar), nyalakan penjaga SSRF sekali di awal:

Sesudahnya alamat loopback, privat, link-local dan metadata awan ditolak. Yang diperiksa alamat hasil DNS yang benar-benar disambungi, juga di tiap pengalihan, jadi nama yang menunjuk 127.0.0.1 tidak lolos.

SQLite

Driver SQLite dimuat dari libsqlite3 milik sistem. dok::db_tersedia() memberi tahu apakah pustakanya ada.

Nilai selalu diikat lewat ?, jadi teks dari pengguna tidak pernah dibaca sebagai perintah SQL. Satu baris hasil adalah dict, dan kolomnya dibaca dengan namanya.

Jaringan tingkat rendah

dok::tcp_listen, tcp_accept, tcp_connect, tcp_send, tcp_recv_line untuk TCP, dan dok::udp_bind, udp_send_to, udp_recv_from untuk UDP. dok::log_info dan kawan-kawannya mencetak log bertingkat, dengan warna di terminal.
